# Domain docs

Use the single-context layout:
- GLOSSARY.md at the repository root.
- docs/adr/ for architecture decisions.

Before exploring, read the glossary and ADRs relevant to the
area. If a document is absent, proceed silently; domain-modeling
creates documentation as terms and decisions are resolved.

Use the glossary's vocabulary in issues, proposals, and code.
Surface conflicts with existing ADRs explicitly.
