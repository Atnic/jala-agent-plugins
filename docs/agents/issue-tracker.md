# Issue tracker: GitHub

Issues and specs live in Atnic/jala-agent-plugins.
Use gh with --repo Atnic/jala-agent-plugins.

- Publish specs and tickets as GitHub issues.
- Read issues with gh issue view <number> --comments;
  include body, labels, author, and dates when triaging.
- List issues with gh issue list, including labels and comments.
- Update labels with gh issue edit.
- Use gh issue comment and gh issue close for outcomes.
- For multiline issue bodies and comments, write a temporary
  file and pass --body-file.
- Every issue or comment posted during triage must start with:
  > *This was generated by AI during triage.*

## Pull requests as a triage surface

PRs as a request surface: no.

For an explicitly referenced number, try gh pr view first,
then gh issue view. Read PR diffs with gh pr diff.

## Wayfinding

Track a map as an issue labeled wayfinder:map and its tickets
as GitHub sub-issues. If unavailable, use a task list on the
map and Part of #<map> on each child.

Use native issue dependencies for blockers; fall back to
Blocked by: #<number> references when unavailable.

The frontier is open, unassigned children with no open blockers,
in map order. Claim by assigning @me. Resolve with a comment,
close the ticket, and link its decision from the map.
