# Reviews and TestFlight

## Customer reviews

Use the customer review collection action to inspect the exact app and rating/date filters first. Read the review and any existing response before drafting a reply. Post a response only when the user asked to respond or approves the proposed wording. Verify the returned response state.

## TestFlight

Use the named actions for builds, beta groups, testers, beta app review submissions, and build assignments. Identify the app, build, group, and tester scope before changing assignments. A successful TestFlight review submission is not the same as App Store review or public release.

Deletion actions use the local approval page. Changes that add testers or assign a build follow the user's direct instruction; confirm which group and build when either is ambiguous.
